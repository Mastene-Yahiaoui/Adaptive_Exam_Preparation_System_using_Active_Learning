Adaptive Exam Preparation System

Using Active Learning & Uncertainty Sampling

A smart quiz platform adapting to individual student levels in real-time.

The Problem with Fixed Quizzes

Static Evaluation 📉

  • Strong students get bored/under-challenged.
  • Weaker students get discouraged early.
  • Grading takes unnecessary time.

Our Solution 🎯

A platform that adapts the quiz path to the student.

Core Objective: Estimate how a student will answer the next question, and choose the most informative one.

⚠️ Crucial Design Choice: Avoiding Data Leakage

Student state features were computed using only previous answers. The current answer was strictly excluded from the feature set to keep the system realistic.

The Embedding Problem (What we removed)

🚨 97% Feature Importance

In the first iteration, text embeddings dominated the model.

  • The Issue: The model learned question text too strongly instead of adapting to student behavior.
  • The Fix: We removed embeddings, forcing the model to rely on balanced student-state and structured question features.

Other removals: IDs, redundant text, post-event signals.

Train-Test Strategy & Active Learning Prep

Group Shuffle Split

Split strictly by session_id (70% Train / 30% Test).

Why? Prevents the model from seeing parts of the same session in both training and testing, inflating results.

Simulating Active Learning

We did not train on the full 70% at once. We started with:

  • 10% Labeled Seed Set
  • 90% Unlabeled Pool

The Active Learning Loop

Using Uncertainty Sampling (Entropy):

  1. Train model on current labeled set.
  2. Predict probabilities on unlabeled pool.
  3. Select samples closest to 0.5 probability (highest uncertainty).
  4. Move them to labeled set.
  5. Retrain. Stop if LogLoss plateaus.

Runtime & Scoring Mechanics

The platform stops adapting when confidence is high (Probability < 0.3 or > 0.7).

Score =
w1(Actual Correct) + w2(Predicted Correct)
Total Questions

Weights ensure actual answers (w1) matter more than estimated ones (w2).

Platform Lifecycle & Limitations

🔄 Continuous Retraining

The platform intentionally collects cases of high uncertainty. Once a threshold is reached, the model is retrained and redeployed to handle new student behaviors and topics.

Known Limitations

  • Dataset Size: Initial dataset was small.
  • Difficulty Proxy: Derived from answers, not pedagogy.
  • Predicted Variables: Response times were predicted via a separate model, not directly observed.

Conclusion

  • Adaptive testing can be efficiently built using real ML pipelines and Active Learning.
  • Student state features are critical for personalization.
  • Uncertainty sampling drastically reduces labeling needs (reached stability with 48% data).
  • XGBoost proved highly capable for tabular, real-time probability prediction.
